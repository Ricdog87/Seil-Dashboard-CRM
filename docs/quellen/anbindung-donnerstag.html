Teil 1 · im Call, in dieser Reihenfolge

Was die IT anlegtIT

Alles im Microsoft-Admin, nichts muss gebaut werden. Zusammen etwa 30 Minuten, wenn ein Global Admin im Call ist.

  1. App-Registrierung in Entra ID

    Name SEIL Automatik (n8n) · Single tenant · kein Redirect-URI (Client-Credentials-Fluss) · unter Certificates & secrets ein Client-Secret, Laufzeit 24 Monate. Notieren: Directory (tenant) ID, Application (client) ID, Secret-Wert (nur einmal sichtbar). Zusätzlich aus Enterprise applications die Object ID der App – sie wird in Schritt 3 gebraucht.

  2. API-Berechtigungen: nur Sites.Selected

    Unter API permissions → Microsoft Graph → Application permissions → Sites.Selected → Grant admin consent. Keine Mail.*- oder Calendars.*-Berechtigungen in Entra eintragen.

    Die Falle: Postfach- und Kalenderrechte kommen in Schritt 3 über Exchange, begrenzt auf genau ein Postfach. Wird parallel Mail.ReadWrite in Entra freigegeben, gilt das hausweit – Rechte addieren sich, die Begrenzung ist wirkungslos.

  3. Exchange: Zugriff auf genau ein Postfach (RBAC for Applications)

    PowerShell mit dem Exchange-Online-Modul. Platzhalter in spitzen Klammern ersetzen.

    # Verbindung
Connect-ExchangeOnline

# Die App in Exchange bekannt machen (Object ID = Enterprise Application, nicht App Registration)
New-ServicePrincipal -AppId <CLIENT-ID> -ObjectId <ENTERPRISE-APP-OBJECT-ID> -DisplayName "SEIL Automatik (n8n)"

# Geltungsbereich: ausschließlich deals@seil.com
New-ManagementScope -Name "SEIL Automatik deals" -RecipientRestrictionFilter "PrimarySmtpAddress -eq 'deals@seil.com'"

# Drei Rollen, alle nur in diesem Geltungsbereich
New-ManagementRoleAssignment -App <CLIENT-ID> -Role "Application Mail.ReadWrite"      -CustomResourceScope "SEIL Automatik deals"
New-ManagementRoleAssignment -App <CLIENT-ID> -Role "Application Mail.Send"           -CustomResourceScope "SEIL Automatik deals"
New-ManagementRoleAssignment -App <CLIENT-ID> -Role "Application Calendars.ReadWrite" -CustomResourceScope "SEIL Automatik deals"

# Prüfen: muss für deals@ "true" liefern, für jedes andere Postfach "false"
Test-ServicePrincipalAuthorization -Identity <CLIENT-ID> -Resource deals@seil.com

    Damit entfallen SPF/DKIM-Arbeiten. Die Automatik sendet über Exchange (Graph sendMail), die Mail verlässt das Haus wie jede Outlook-Mail und landet in „Gesendet“ von deals@. Kein fremder SMTP-Server im Spiel.

  4. SharePoint: Freigabe je Site

    Zwei Sites bestimmen: die mit der Liveliste (Lesen genügt) und die mit den Mandatsordnern (Schreiben – Modul 01 legt dort 00_Datenraum light und 99_Datenraum an). Freigabe per PnP:

    Grant-PnPAzureADAppSitePermission -AppId <CLIENT-ID> -DisplayName "SEIL Automatik (n8n)" `
  -Site https://<tenant>.sharepoint.com/sites/<liveliste-site> -Permissions Read
Grant-PnPAzureADAppSitePermission -AppId <CLIENT-ID> -DisplayName "SEIL Automatik (n8n)" `
  -Site https://<tenant>.sharepoint.com/sites/<mandate-site>   -Permissions Write

    Dann die IDs, die n8n braucht (Graph Explorer, als Admin):

    # Site-ID
GET https://graph.microsoft.com/v1.0/sites/<tenant>.sharepoint.com:/sites/<liveliste-site>
# Item-ID der Liveliste
GET https://graph.microsoft.com/v1.0/sites/<SITE-ID>/drive/root:/<Ordner>/<Liveliste>.xlsx

  5. Live-Test im Call

    Wir legen in n8n das Credential an (Teil 2, Schritt 1) und führen WF 06 einmal von Hand aus: Es muss die ungelesenen Mails aus deals@ zurückgeben. Scheitert das, ist es fast immer Schritt 3 – und wir sind alle noch im Call.

  6. Optional, nur Termin vereinbaren

    DNS-Eintrag n8n.<domain> → srv2104755.hstgr.cloud für eine saubere Adresse (heute funktioniert der Hostinger-Name). Zweite App-Registrierung für den Microsoft-Login am Cockpit (Stufe 3) – braucht einen Redirect-URI, kommt mit der Entscheidung zur Produktivbasis.

    n8n → Credentials → OAuth2 API (generisch). Grant Type Client Credentials · Access Token URL https://login.microsoftonline.com/<TENANT-ID>/oauth2/v2.0/token · Client ID · Client Secret · Scope https://graph.microsoft.com/.default · Authentication Body. Freitag

Was dann geht – und was nicht

Geht, wenn Donnerstag vollständig landet

  • WF 06 liest deals@ live, klassifiziert nach Standardprozess
  • WF 03 formuliert Entwürfe mit Claude innerhalb der Vorlage
  • Freigabe per Mail-Link an die Leitung, Versand aus deals@ nach Klick
  • Besichtigungstermin im Kalender von deals@
  • Matching gegen die echte Liveliste
  • Cockpit zeigt echte Datenraum-Stände, sobald Modul 01 auf dem SEIL-Server einmal gelaufen ist

Geht Freitag nicht

  • Team arbeitet im Cockpit mit bleibenden Freigaben und Notizen – keine Datenbank, keine Anmeldung (Stufe 3, 2–4 Wochen)
  • Nachfass-Stufen über Tage hinweg – brauchen die Tabellen aus Teil 3 und mindestens zwei Tage Laufzeit
  • Schwärzung, falls sie in Modul 01 noch fehlt
  • WhatsApp (Superchat-Vertrag offen)
